# Synthetic surveys

Synthetic surveys (class C3) are generated by the `synth` module from known spatial
fields and a fixed seed. They are regenerated when needed rather than committed:

```r
library(nansenbiomass)
sv <- synth_survey(synth_design(), seed = 1)   # survey, truth, strata, stations
write_biotic(sv, "synthetic/synth-seed1.xml")  # NMDBiotic v3.1, marked SYNTHETIC
```

What makes them synthetic, and plainly so:

- Every value comes from closed-form fields (depth, a smooth spatial effect) and a seeded
  observation model. Nothing is derived from real records: no rounding, jittering or
  subsampling of real data (CLAUDE.md, rule 6).
- Identifiers are artificial (cruise `SYNTH0001`, platform `SYNTHETIC`, year 2000,
  species `SYN001` to `SYN003`, gear and platform code `9999`).
- The domain is in the open South Pacific (30 S, 120 W), far from any programme area,
  with shelf depths that do not exist there.
- `write_biotic()` writes only objects flagged as synthetic, and every file it writes
  starts with a `SYNTHETIC SURVEY` comment.

`.gitignore` allows XML, DuckDB and RDS files in this folder. Commit a generated file only
when a later milestone needs a fixed fixture (for example a StoX project at M2), and say so
in the commit message.
